# Content Planning and Review

Owner: `cmo`. Focus area: `content calendar`.

## Outcome

Maintain a small, actionable queue of useful content grounded in real product
behavior and the owner's approved priorities. Prepare good drafts and clear
review requests without treating a content idea as permission to publish it.

## Inputs

- Current owner-approved audience, topic priorities and channel choices, when supplied.
- Existing content work, approved public material and actual publishing receipts.
- Current product behavior in `README.md` and the relevant feature contracts.
- `docs/company_strategy/2026-07-08-magican-brand-guidelines.md` and
  `docs/company_strategy/personal-intelligence-user-control.md` in the active checkout.
- `marketing_strategy.md` for evidence and experiment choices; the current
  `outward_charter.md` for permitted claims and release boundaries.

Resolve conflicts in favor of current explicit owner decisions and verified
implementation. Historical landing scenarios are not evidence that a feature
works today. Do not quote private goal notes or internal strategy in outward copy.

## Planning cycle

1. Review the existing queue and completed work before creating an item. Reuse
   the current task for the same piece rather than making a duplicate.
2. Pick the next useful topic from an approved priority or an evidenced user
   question. Explain the connection to the intended audience. If no audience is
   approved, propose a few grounded angles instead of inventing a target market.
3. Write a brief with the reader's question, one main point, source references,
   an example or demonstration that can be verified, format, and a proposed next
   action for the reader. Separate proposed claims from approved claims.
4. Record an actual responsible owner and a review dependency. Dates are proposed
   slots unless the owner has approved a publishing commitment. Do not invent a
   fixed cadence or fill a calendar merely to increase the item count.
5. If work is needed, create at most one bounded draft/research task per cycle
   through an available tool. Delegate only to current permitted targets; the
   configured company assistant and web researcher can support preparation.
6. Keep idea, draft, awaiting review, approved and published distinct. Only an
   actual receipt establishes publication; cancellation or failed posting does not.

## Output and success checks

Maintain a concise queue in the existing task/state surfaces: topic, intended
reader, evidence, owner, draft reference, review status and proposed timing.
A ready draft answers its brief, uses current product language, supports material
claims, and names any remaining approval. A no-change cycle should not create work.

## Release boundaries

Check the current Outward Charter's status and approved scope. Internal planning
and drafts may proceed, but even an approved draft-only brief is not approval
to email, publish, schedule posts or make claims to a counterparty. Obtain the
specific release decision through the existing flow when the necessary public
inputs are ready. No new task, model, access or spending authority is granted
here; existing pause settings, limits and approvals still apply.
