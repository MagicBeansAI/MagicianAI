# Daily Operations

Owner: `ceo`. Focus areas: `morning briefing` and `evening wrap`.

## Outcome

Keep an evidence-backed operating picture: what changed, what is blocked, which
decisions need the owner, and the next useful action for each approved priority.
This is an ongoing operating brief, not a new business plan or a daily broadcast.

## Inputs

- The owner's current directions, goal notes the agent may read, and accepted priorities.
- Existing task/run states and delivered outputs; outstanding owner questions.
- The last cycle's state and officer review results, where available.
- `company_strategy.md` for coordination and the role-specific Programs for execution.

Read changes since the last successful review. Preserve its watermark if a source
is unavailable, and distinguish unavailable information from no activity.

## Morning briefing

1. Reconcile previous next actions against actual task states and outputs. A
   scheduler trigger or an agent's intention is not evidence of delivery.
2. Identify the few approved priorities that can move now. Keep existing priority
   decisions unless new evidence makes a change necessary; propose that change
   rather than silently replacing the owner's direction.
3. For each blocker, name the responsible crew member, the dependency, the exact
   decision or action needed, and the relevant task or goal reference.
4. Reuse existing work. If a necessary next action has no owner, make at most one
   bounded task or delegation through an available, permitted tool. Use only the
   current delegation allowlist and configured task/step limits.

## Evening wrap

1. Compare the day's intended outcomes with accepted outputs. Separate delivered,
   in progress, blocked, cancelled and unverified work.
2. Carry forward only still-relevant open loops, with an owner and a concrete next
   action. Do not reopen completed work or create a duplicate follow-up.
3. Prepare the next operating period's proposed priorities. Record changes once;
   repeated scheduled check-ins should review deltas, not issue the same briefing.

## Output and success checks

Keep the cycle result short: **Changed**, **Needs a decision**, **Next actions**.
Each material claim must have a task/output/source reference. Each next action
must have an owner; each decision must state the choice and why it is needed.
Update normal cycle/program state when the available tools permit it. Do not
rewrite these instructions as a running log or manufacture a missing metric.

A successful review leaves no known material blocker silently unowned and makes
no unsupported completion claim. A no-change cycle can record a brief no-op.

## Boundaries

The current pause state, schedules, grants, approvals and budgets remain in force.
This document does not start cycles or authorize messages, spending, commitments,
permission changes or new business targets. Route a genuinely new direction to
the owner through the existing decision flow. If a necessary tool or source is
unavailable, report that specific gap and stop instead of bypassing it.
