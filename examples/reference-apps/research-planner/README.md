# Research Planner reference app

Current base package: `research-planner` `0.1.1`. Companion update candidate:
`0.2.0`. This is an external source/conformance reference for supported-public
Apps contract `1.3`; it does not claim live-owner or release qualification.

The TypeScript client imports only `@magician/apps` and uses exactly the eight
fixed public data-plane operations. Package generation, packing, candidate
publication, update coordination, and portability use only public `magician
app` commands. There are no private HTTP routes, raw provider requests,
generic request helpers, internal task/execution identifiers, or handwritten
generated contract bytes.

## Reference set

- `app/` is the complete base pack root.
- `../research-planner-composition-destination/app/` is a tiny real package
  with one typed `accept_plan` action. Three distinct installations of the same
  immutable package form the bounded composition proof.
- `../research-planner-update-v0.2.0/app/` is a complete update pack root, not a
  patch overlay. Its sibling migration file adds nullable `reviewed_at` and
  retires `revision_note`.
- `owner-fixtures/` stays outside every pack root. It supplies the reviewed
  `research_outline.normalize`, sealed `research-planner-worker.agent_as_tool`,
  and Browser physical-owner source marker used during dependency locking.

All generated `.magician/app-derived.json` and `sdk/app.generated.ts` files are
current owner output from `magician app check --write-generated`. The public
reference-set flow checks and tests all three roots, then creates fresh package
archives without transferring approval or installation authority. Consumer
guards continue to reject reintroduced sentinels or drifted generated bytes.

## Runnable source surface

| Scenario | Proof |
| --- | --- |
| Normalized state and schema forms | `NormalizedEntityState`, exact action-form validation, and bounded detail/form/section/list/table declarations |
| Data plane | strict pagination, optimistic keyed mutation, monotonic changes/reset refetch, bounded callbacks, and cross-install correlation checks |
| Durable actions | intent persisted before launch, opaque run recovery, policy-withheld retention, and generation-bound cancellation |
| Composition | `composeBuildPlanInto` drives one first hop plus two continuation hops, unique hop keys, exact mappings, and payload-free cursor resume |
| Recipe | six real `runner: recipe` workflows/actions consume immutable package members for Query, Query→Get, Map, Sequence, Parallel, and Switch; collectively they execute Query/Get/Map/Validate/EmitValue/Sequence/Parallel/Switch |
| Auto dependencies | `time_math.date_range`, `research_outline.normalize`, vendored `skill:plan-brief`, sealed agent-as-tool, and four singleton Browser `snapshot`/`navigate`/`scroll`/`click` leaves with exact reviewed origin/session posture |
| Memory | `build_plan.plan_memory` is a reviewed mutation-backed `research_plan` contribution proposal with one user-memory destination, hypothesis evidence, rate ceiling, and retention ceiling |
| Lifecycle | behavioral fake-CLI tests execute candidate publication, destructive update plan/backup/review/approval, and correlation refusal |
| Portability | behavioral fake-CLI tests execute encrypted data/combined export, preview, approval, and commit into an explicit compatible destination |

`src/recipe-fixtures.ts` is the deterministic source for the six Recipe bundle
members. `npm run recipes:materialize` rewrites `app/recipes/*.json`; the
package-source test requires semantic byte content to remain equal to the
executable provider-free fixtures. This is not a second arbitrary Recipe
interpreter. The runtime and package lock remain the canonical admission and
execution owners.

## Deliberate refusals

- Recipe `Retry`, `MarkUncertain`, mutation, tool/action/procedure/agent calls,
  artifact/receipt emission, and other effectful nodes stay denied by the
  current Ready lowering set.
- P6 memory and retrieval owners are implemented, but this package declares
  only its bounded mutation-backed `plan_memory` proposal. Destination-specific
  attention/notification and canonical task/plan proposals remain deferred;
  the sample does not approximate them with app-owned writes.
- A missing reviewed physical owner returns typed unavailable. The reference
  never falls back to raw browser/macOS/Android controls, selectors, session or
  tab IDs, provider handles, CDP, shell, or argv.
- An uncertain keyed effect never triggers guessed rollback or a changed-input
  retry. An expired/gapped composition cursor never authorizes a guessed hop.

Machine-readable refusals live in `src/refusals.ts` and
`fixtures/refused/unsupported-public-paths.json`; malicious fixtures invoke the
consumer guards and assert behavior, rather than merely scanning strings.

## Clean-checkout order

From this directory:

```sh
npm ci
npm run recipes:materialize
npm run test:static
```

`prebuild` compiles the sibling `sdk/typescript` package before compiling this
consumer. The provider-free static suite excludes the two explicit canaries.
Run `npm run test:contract-canary` where a local loopback listener is available,
and run `npm run test:real-server-canary` only with
`MAGICIAN_P4_REAL_SERVER_ORIGIN` pointing at the authenticated fixture owner.
The repo-level `make test-app-typescript-consumer-canary` additionally
copies the project and SDK into a fresh tree, packs/installs the private SDK
tarball, then compiles and runs the external consumer. Neither path relies on a
checked-in `node_modules` or stale SDK `dist`.

After the current Magician binary is available, generate and pack all three
public sources:

```sh
npm run app:pack-reference-set
```

That script runs only public `check --write-generated`, `test`, and `pack`
commands. It is intentionally create-new/no-overwrite. Review each generated
pair and archive before any live publication.

The exact public pack→candidate→review/approve, destructive update/reinstall,
rollback/rewind, and encrypted data/combined portability paths are in
[LIFECYCLE.md](./LIFECYCLE.md). `scripts/public-lifecycle.mjs` executes the
publication, update/reinstall, and portability sequences; rollback/rewind stay
separate owner decisions documented there.

## Client boundary

Construct `ResearchPlannerClient` with one current public origin, installation
ID, and surface revision. `launchBuildPlan` requires a durable recovery adapter
and saves installation/action/input/idempotency intent before dispatch. Only a
canonical run snapshot discloses terminal output.

`composeBuildPlanInto` accepts an opaque source run, a first destination, at
most two continuation hops, and an optional cursor. The fixed first mapping is
`plan_id -> source_plan_id`; callers declare subsequent mappings. The broker,
not the client, retains source result bytes and reopens every reviewed binding.

Entity change consumption is strictly paged, de-duplicates records/cursors,
rejects schema/authority identity drift, and refetches on `reset_required`.
Caller abort stops a wait only; server cancellation remains the separate
generation-bound public operation.
