## [Unreleased]

### 2026-11-02 — 0.7.151

- A delegated agent's approval gate reaches the owner. A delegated run that paused for an approval rule or a confirmation-gated tool (an agent edit, an install) was force-failed and cancelled within a second and its approval card suppressed, so gated work inside a delegation could never be done and the parent re-delegated it in a loop. The child now parks as waiting for the owner, its card is published, the parent waits on it, approving resumes the child and denying settles it failed; cancelling the parent still cancels it. Receipts sealed before the upgrade keep the old force-failure.
- God mode set in a chat reaches the coding work it starts. An agent that holds `run_coding_task` (the senior developer, the engineers), and the VibeDev Build and Discuss coordinators, got no god session at all, so in a god-mode chat their `delegation_files`, `delegation_shell`, `shell` and file calls still hit the normal sandbox and were refused without asking. They now follow the chat's choice like any run (`god_session_for`, `plane_god_session`, `god_mode::current_session`). Their shell stays in a box that keeps the live Magician repo and the run's real repo unwritable, and a call aimed at either always asks, allow-once only (it then runs unconfined); the coding engines themselves stay boxed, and super god mode still lifts that.
- A chat turn cut off by a restart no longer shows as running. Its state lived only in memory, so the new process reported none and the page treated the unanswered turn as live (Stop did nothing) for 10 minutes. The startup sweep now reads each turn file's last state row and settles a `running` one that began before this process as failed (`interrupted`), or as completed when its reply was saved; when it is still the session's newest turn it becomes the session's `turn_state` again.
- A chat-spawned task resumed after a restart posts its result into its chat again. Its watcher died with the old process, so the resumed run finished and the chat never heard; startup now re-registers the chat fan-out and starts the delegate watcher for every resumed run of a task the chat itself launched (`created_by: chat_*`) (`rearm_chat_delivery_for_recovered_tasks`). Children of runs and scheduled runs are left alone.
- A chat turn starts no new work once shutdown begins. A turn finishing during the HTTP drain could still launch a run seconds before the supervisor's kill, leaving it cut off mid-step; chat pack, delegate, handover, sub-goal and pipeline calls now answer `runtime_draining` ("Magician is restarting…") from the shutdown signal on. Runs already executing and scheduled cycles still launch theirs, and restart recovery resumes them.

### 2026-11-02 — 0.7.150

- Muse (`creative-mind`), `presentation-maker`, `frontend-engineer` and `junior-frontend-engineer` can activate the Impeccable design procedure. Only the two coding agents carried it, so a deck run reported Impeccable as unavailable and fell back to `presentation-design-principles`.
- A failed tool call says why on harness turns too: a plane tool that ran and failed records its result text as the `tool.failed` error (it was empty), the error is scrubbed of values delivered to the run, and every producer's `tool.failed` error is capped at 2,000 characters.
- A parent that delegates right after the owner answers its question resumes when the child finishes. That resume path never saved the Delegation checkpoint, so the child's result had no hand-off, generic recovery saw the parked segment's pin as a live owner ("already owned by a live generation"), the retry was acknowledged without resuming, and the reconciler later failed the task. Every resume path now saves the checkpoint through one writer; generic recovery defers a segment parked on children without one; a resume refused as owned retries when the ownership ends, and its wake re-sends the resume instead of acknowledging it.
- A chat turn with large images is no longer refused as over budget. The pre-send check counted the built request's bytes, so two multi-MB screenshots weighed millions of tokens and every later turn failed with "current images, files or active turn exceed this model's input budget"; images now count at the flat per-image rate (`magicllm::estimate_messages_input_tokens`), as providers bill them, and the request copy of an image longer than 1,568 px is scaled to that long side, as providers do anyway (the stored file is unchanged; one that cannot be fitted becomes a note naming the file). A request carries at most 12 MiB / 50 images: the current turn's images always go, then the newest earlier ones, and older ones become a note; a provider's request-too-large error now triggers the compaction retry. The agentic loop's verbatim window counts screenshots the same way, so one screenshot no longer evicts the earlier turns.
- A shell call that runs out of time says how to give it longer: rerun with a larger `timeout_secs`, or run installs, downloads and builds with `background=true` and poll `action=status` (the shell guide says so too). An identical repeat of a timed-out shell call is no longer treated as a transient blip, and lineage records it as a timeout. Task shells may write clang's module cache (`…/C/clang/ModuleCache`), so `swift` scripts and `clang -fmodules` run there; the rest of the per-user cache dir stays read-only. A failed tool call's journaled error keeps up to 2,000 characters, ending in `…` when cut (was a silent 240).
- The `grep` and `glob` agent tools always have a ripgrep, and say so when they do not. They ran whatever `rg` was on the service's PATH, so on a machine without one (a desktop install, whose setup never installed ripgrep) every search failed with "Failed to spawn ripgrep" and agents fell back to slower shell `grep`/`find`. They now run Magician's pinned copy first: the package ships `rg.bin` beside `magician.bin` (from the `@vscode/ripgrep` copy pinned in `skillshub/package-lock.json`), then the `rg` skill's copy, then the host's `rg`; `MAGICIAN_RG` overrides. With none, both refuse with `ripgrep_missing` and the fix, the startup log says so as an error, and `/health` reports `tools.ripgrep`. Desktop setup installs ripgrep, and `install.sh` warns when a host-run backend would have none. On Windows the lookups use `rg.exe`.
- A workspace's first memory index is built about a minute after its first memory write. Until the index exists every retrieval is lexical only, which misses facts not near a turn's start, but the first build waited for the usual quiet period (up to 30 minutes while writes continued) and, after a failed first attempt, the 15-minute retry cooldown: a fresh workspace's index appeared about 20 minutes after its last write. A workspace with no usable index now builds after the quiet period or at one minute, whichever is first, and a failed first build retries after 1 minute (doubling to the hourly cap) instead of 15; a workspace with an index keeps the usual debounce and cooldown.
- A run whose parent waits on delegated agents no longer shows as paused. A task-backed goal cycle that settled on `waiting_for_children` wrote the task `paused`, so the notch, the work list and the phones showed a working run as paused until the parent resumed (11 minutes in one run). It now leaves the status the reducer wrote, `running`; a wait on the owner or a pause still reads paused.
- The VibeDev coding agents can check and install a skill from the repo's `skillshub/` when asked: `validate_skill` runs the SKILL.md validator, `test_skill` runs the skill's offline tests and `install_skill` installs it into the caller's workspace, the same linked install as the Skills page. Chat reaches them by delegating. Testing and installing ask the owner first (Approve Once / Deny; no answer in 5 minutes is Deny). Their Python runs without the service's provider keys or tokens, they read the live checkout (a change made in an isolated workspace counts once applied), and none of them is reachable from a Claude Code or Codex plane consumer. Before, a coding run that added a skill could not install it: it had no way to ask for a write outside the repo.
- Impeccable (upstream `skill-v4.8.0`) ships in `skillshub/impeccable` as an instruction-only design procedure with its 24 workflows as local references. The upstream launcher, detector, hooks and editor installers are not included.
- An agent can open the files its active playbook links to. Only a procedure skill's SKILL.md body reaches the prompt, so a playbook that keeps its detail in `references/` (Impeccable's 24 workflows) showed the agent links it could not follow: it was not told the folder, and the folder is outside the file tools' roots. `activate_skill` now takes an optional `file` and returns it when the playbook links to it, and the playbook names its linked files under its body. Nothing else in the skill folder is readable, so its `config` and `auth/` state never reaches the model. The coding engine, which cannot call `activate_skill`, gets the linked files in its prompt.
- The coding agent's persona and active playbook (with the files it links to) reach every VibeDev coding engine, not just Pi. Claude Code, Codex, Grok and Antigravity dropped both without a word, so a run pinned to one of them coded without the agent's identity or its playbook. Claude Code now gets them through `--append-system-prompt` on every launch, Codex as `developerInstructions` when a thread starts, and Grok and Antigravity as a fenced block ahead of a new session's first prompt; a file that cannot be read is logged with the engine's name. A Codex, Grok or Antigravity session resumed from before the change, or after the persona or playbook changed, keeps what it started with.
- A skill's runtime contract can take its server from the workspace: `${NAME}` as the origin of the MCP endpoint, its endpoint aliases or the OAuth issuer is read from that workspace's own skill `config/.env`, never the server's environment or another workspace's. One `SKILL.md` therefore serves every workspace through the usual links, and loading, Connect, the run and the Skills page all resolve it the same way, so a sign-in and the runs that use it name the same server. An unset or invalid value withdraws the skill in that workspace with the variable named; an unreadable `.env` is held back like any load failure. A changed value rebuilds the skill, and a withdrawn one is not kept serving the old server. The reconciler relinks a manifest the retired per-scope renderer wrote while its content still matches; an edited copy is left, and said once.
- Tool skills run where they say they do. An entry point that resolves to a script inside an installed npm package (a skill's `bin/` link onto agentmail-cli's, tgcli's or the Higgsfield CLI's JS launcher) is refused when the skill resolves, naming the skill and the fix (a self-contained adapter or a native binary), instead of failing every call once the launcher ran from its private copy without the files beside it. A CLI-owned-login skill in workspace mode (ocr) now runs in the task's workdir, else its own per-call folder, like every other route, not in Magician's own folder (the repository on a dev host, where its relative input missed the task's files and its output landed); a `working_directory: denied` skill always runs in its own empty per-call folder.
- A skill whose `config/.env` lists an optional key with no value (`REDDIT_CLIENT_ID=`) runs again. The empty value reached the runtime, which refuses empty credential material, so every reddit-search call failed before it started; `KEY=` now reads as unset, as it already did for a required key (which still fails as missing).
- The "where should Magician work?" question can be answered on the web. It was announced with the private input type `work_location`, which the web drops, so it showed as plain text in the composer, the deep panel and Attention and could not be answered (iOS rendered it). It is now a `choice`, and a user request with any non-canonical input type is announced as a `choice` (with options) or `text` (without), so one producer's spelling can no longer make an ask unanswerable. An answer sent as an option's label (iOS replied `provide_input` + "Original folder") now counts as that option; it was read as no choice, so the coding run was refused after the owner had answered.
- A task that ends cancelled or retired no longer always publishes its answer as "Not fully verified … evidence reviewer was unavailable". The claim review of a terminal answer was bound to the task's cancellation, so the dispatch queue dropped every review call (`task_cancelled_pre_dispatch`). It is now exempt like the terminal synthesis it checks; an explicit cancel of the execution still stops it.
- `run_coding_task` works again on a repository that tracks a symlink (this one tracks `.claude/skills/anatomy`). Each run re-syncs the repository into the same persistent shadow workspace, and re-creating a link the previous run had left failed with `File exists (os error 17)`, so every run after the first stopped at `prepare_shadow_workspace`. The sync now keeps a link whose target is unchanged and replaces any other leftover entry. A file or folder that replaces a link is no longer copied through the old link.
- An agent that aims a coding turn or a git command at a repository outside Magician's workspace now asks the owner where to work on it, once per task: Isolated workspace (the default: a copy, changes back as a diff to approve), Isolated branch (a git clone on a `vibedev/…` branch) or Original folder (edits held for approval), or Cancel. The question says when the folder is Magician's own source code. The answer makes the folder a VibeDev project and binds the task to it, and the same call then runs; every later call and delegated hop of the task uses that project without asking, including its build cache and project checks. A folder an existing project owns binds without asking, parallel calls share one question, and a Cancel holds for the rest of the run. A task works in one project: a folder of another project is refused, naming the task's project, and the home folder or anything above it is too broad to ask about. Before, a chat-delegated `run_coding_task` bound the model's raw path (the live Magician repo in one run) while `git status` on it was refused. Magician's own source tree is now refused to a coding turn whose task's project does not own it, as the shell already did.
- A run ends at the first failure that is Magician's own instead of retrying it: `run_coding_task` marks setup failures the model cannot fix (its folders, the engine install or version, the adapter, a missing credential for the default profile, or a project repository a clone cannot use) `"fault": "platform"` with a `"fix"` where one exists, and the loop ends failed with "Magician couldn't run this because of a problem on its side, not with your request: … " (or, for the repository, what to fix there). Only `run_coding_task`'s own result counts, and a profile the model chose that cannot run is the model's to change. A delegate that ends on one ends its parent too. Before, a developer agent called `run_coding_task` 14 times on an unsupported Pi version and then started debugging Magician's source.
- An inline sub-goal (or in-context delegate) that ends no longer ends the whole run. Its final outcome previously settled the root execution, which then completed with the sub-goal's partial summary as the user's answer; the parent's next phase also failed with `operator_steer_inbox_terminal_fence_binding_mismatch`. A nested segment's final outcome now retires only that segment: no runtime settlement receipt, no steer fence, no root task-state close, work-ledger or execution-summary write, and no `AgenticExecutionCompleted` event. The parent continues with the child's result. Pauses inside a sub-goal keep their receipts.
- Web page reads (`static_http.read`) and tinyfish discovery work again for every agent except the admin agent. Since goal workspaces, a governed workspace-mode CLI that had no task work root ran in the scope root, which contains other tasks' restricted evidence, so the goal-workspace guard refused every call. Such calls now run in their own per-call lease, created after admission and removed when the call ends; the guard is unchanged.
- Files an agent produces now reach the user. `yield` takes `deliverables: [{path, title?}]` (an absolute path or one relative to the task workdir, the first entry being the primary). Bad items are dropped, never failing the yield. `export_result` writes and shell/file-writing tools' top-level `path` results are captured as output files. A run that declares and captures nothing gets a terminal sweep that promotes task workdir files named in its answer, skipping repositories. Delivered files become `user_attachment` outputs at `/api/magician/v3/tasks/{task}/outputs/delivered/{exec}/{name}`. Task refs record `primary_deliverable_output_id` and `latest_delivered_output_ids`. Outputs and chat file blocks carry `primary`, and `delivered_files` is added to the delegate result and task details. User-facing summaries and the chat "Done." message no longer contain host paths or `file://` links: a delivered file's path becomes its served link (prose only, code left as written), and the "Done." message lists the files from that run.
- Answer synthesis sees the files delivered with the answer: name, title, size, served URL, primary flag, and an excerpt and outline of the primary file. It links the primary deliverable instead of repeating it, and the claim check treats those links as runtime facts. Host paths and `file://` links are rewritten in HTML answers too (links, attributes and text; code and markup kept) and in JSON answers (string values only). Verified-file answers stay byte-identical; their summary links them by served URL.
- Threads get a URL slug that follows their name (`UiThreadRecord.slug`). Former slugs are kept in `ui_thread_slug_aliases`, so old links still resolve, and `UiThreadService::resolve_thread_key` resolves a key as id, then slug, then former slug. Existing threads are backfilled with slug = id, except a thread stored under the reserved id `new`, which gets a slug from its name. A rename moves the slug, `general` keeps its slug, and no thread is ever created with id or slug `new`.
- Agents finish once they have the deliverable: a long result goes to a workdir file declared in `yield.deliverables`, and the final message is the requested artifact, never an audit or delta report. A chat-delegated goal restates the user's request and the deliverable they asked for, without adding verification or sourcing rules they did not ask for.

### 2026-10-31 — 0.7.149

- A delegated agent that delegates in turn (assistant → CEO → department agents) resumes when its own children finish. Two things stopped it. Its `agent.cycle.completed` event carried a `running` status hint that overwrote `waiting_for_children` two seconds after it parked, so the parent resume refused it; and the resume activated it through the root-only activator, which refuses while the root waits on it. A park on children now ends only through the runtime's status transition or a resume-type event (an LLM call, iteration or cycle event cannot end it), and a delegated parent resumes through its own activation, leaving the task's active root alone. A hint-less event that arrives after a root ended no longer makes it the task's active root again. The resume logs each reason it declines.
- A terminal parent whose stateless handoff names a segment the reconciler retired drops that stale descriptor (`SourceEndedWithoutHandoff`) instead of failing its child-completed wake every 30 seconds.
- A cancellation the runtime forces on a delegated child records `Cancelled by the runtime: <reason>` (one line, at most 300 characters), not `Workflow event: UserCancelled`.
- A harness cycle the owner stops (pausing Team routines mid-cycle) no longer opens a `cycle_failed` anomaly, so autofix is not sent to "fix" a cancellation.
- App package import rejects an archive that repeats a member name; zip kept only the last copy, so the duplicate check never saw the pair.
- zip 9 (RUSTSEC-2026-0367/0368/0369) and actix-http 3.20 with zstd 0.14.3 (RUSTSEC-2026-0391, -0398, -0403). App package import rejects a ZIP member whose name zip 9 cannot decode as an unsafe member, like an overlong or non-UTF-8 name.

### 2026-10-30 — 0.7.148

Compact long chats reliably, sized by the summarizer's window, and search their full history; list attention asks in the lane of what they need; speed up `/llm` analytics; keep whole-call tool constraints out of provider schemas; Town Square budget and resurfacing fixes.

- Chat on Anthropic models no longer fails with "input_schema does not support oneOf, allOf, or anyOf at the top level" when the `shell` or `content_*` tools are offered: their whole-call constraints stay in the canonical tool schema for candidate construction, proposal validation and dispatch, and the provider adapters and the plane MCP catalog restate them in the tool description instead of the schema root.
- `/llm` analytics batches build their reconciled `llm_calls` window once in memory (also for `epoch_ms(now() - INTERVAL …)` windows, now recognised as safe bounds) and release the analytics guard before running up to 16 cards; today's legacy `batch_*` LLM files fold hourly or at 64 files instead of staying raw until midnight; folded batches and superseded generations stay readable for 15 minutes before deletion so readers that chose them just before a fold keep working; queries past the batch cap get an explicit error result instead of being dropped; the LLM Parquet sink no longer waits unboundedly for the guard and the canonical fact compactor waits 30 s instead of 5 s. The DuckDB tool's `read_parquet` `llm_calls@` shorthand now reads the same manifest-selected files, so it no longer counts folded rows twice or picks up the `part-*` fact files.
- Town Square stops burning and misreporting its budget: an app model attempt the provider definitively rejected (typed HTTP 4xx other than 408/429) now releases its reservation instead of holding it until the month ends; a contextual round in which every tried participant failed ends the run `failed` rather than `completed`; behavior health no longer shows a `period_resource_ceiling` error after its period has ended; and consecutive failed runs of a recurring behavior back off (the interval doubled per further failure, at most 64× and one day) instead of relaunching on the interval, until a run completes.
- Preserve evidence-linked findings through task finalization and check delivery coverage separately from factual support.
- Attention asks land in the lane of what they ask for: service outages and failed agents under Failed, plan/diff approvals and action confirmations under Approvals, iteration-limit and budget pauses under Escalations, questions and sign-ins under Requests. Previously almost every ask was listed under Requests. An open ask under Failed no longer expires after two hours.
- Chat history compaction is fast and no longer fails on chats with an earlier failed turn: older tool output is trimmed to head and tail before summarizing, each summarizer call is sized to the routed summarizer model's input window alone (a long chat folds in one or two calls instead of dozens; `llm.chat_history.chunk_max_bytes` is removed, so delete it from the live config), compaction runs in the background past 70% of the budget so turns rarely wait, and the step shows **Compacting conversation · k/N**. Compaction now works in stored-transcript positions and maps onto the turn's healed request, which previously made the final save fail ("chat changed during compaction") after every summary call had run. A summary or save failure never fails a turn: a history that still fits is used in full. Text sent to the summarizer is redacted like provider replay. A compacted chat can look up exact details with the new `search_chat_history` tool, which pages long entries and whose results never count as proof of a reply.
- Browser runs treat agent-browser's `outcome_unknown` (a command that reached its daemon with no reply, and was not re-sent) as INDETERMINATE: the agent is told it may already have taken effect and to re-observe before repeating it. CloakBrowser's session-limit exit is recognised again in the patched agent-browser's wording ("Browser process exited (exit code: 76)"), so the run switches engine instead of failing.
- Tool-result cleanup probes metadata with bounded concurrency and locks only matching owners.
- A browser run launched by a conversation's first message names its tab group from that message: the conversation is titled only after its first turn, so these groups showed "✱ Chat".
- Browser runs name their tab group in the owner's Chrome: a chat launch sends the conversation's title, and any other run sends its task's title (first sentence, without the agent prefix), as Magicutor's `?label=` on connect. The same name appears on the "which browser?" card instead of "this task". Carried as `browser_tab_label` beside `browser_session_id_override`.
- Native chat now budgets model context, saves incremental history summaries and retries context overflow once while retaining the full transcript and completed tool results.
- The owner-text check (Relentless reports, chat replies, owner notifications) awaits its claim checks and delivery repair off its own frame. The delivery repair's inline LLM call had made this future large enough that a Relentless task settling at its iteration limit after an answered question overflowed its 2 MiB stack.

- The memory lifecycle pass no longer re-parses an unchanged multi-megabyte `knowledge.json` (up to three parses per run, every minute per scope): its unlocked reads share one parse keyed by size, mtime and inode (never within the 3 s racy-mtime window, dropped by every store write), and its maintenance check is read-only. Memory connection reviews get an outer timeout derived from their 60 s decision budget (`REVIEW_TIMEOUT`), and reviews that end before any decision are `deferred` instead of charged to the hourly budget.
- The shared `knowledge.json` parse is bounded (dropped after 5 min unused; at most 16 files and 32 MiB of summed file size, least recently used first). `ConnectionDecisionUnavailable` now wraps and prints its root cause. Rollback note: earlier binaries cannot deserialize the new `deferred` memory connection state.
- The notes search index no longer deletes its embeddings when an Ollama readiness check is slow (about 30% exceeded the old 200 ms limit) or an embed fails; the next refresh with Ollama embeds only the changed notes. Each such blip used to re-embed every note (~1,450 chunks, five minutes of the single Ollama slot, holding memory-index embeds for up to two minutes). Background refreshes now wait out the configured health timeout; searches keep the 200 ms budget.
- Note writes (create, save, front-matter edits, deletes) reply as soon as the file is written: the search-index refresh is queued in the background instead of awaited, so a slow embedder no longer holds a Mark done on a goal at "Saving…" for minutes.
- The 5-minute memory contradiction sweep no longer re-sends the same insight pairs to the decision engine every run (~8,300 calls/day for one agent): identical copies of an insight are folded into one item without a model call (also during `upsert_by_similarity` merges, which used to append a copy whenever review abstained), and a pair the engine answers below its gate is remembered until the engine revision changes; timeouts and other transient failures are still retried.
- Agent storage opts into memory temperature counter write-behind (`MemoryStorage::shared_handle`): a chat turn's usage and outcome counters share one overlay write per 2 s instead of rewriting the overlay each time.
- Chat turns spend less CPU on repeated parsing: procedure YAML is parsed once per file revision (shared by the procedure lookup, reflection and decision review), parsed skills are reused until a skill file changes, the trust policy is parsed once per content revision, and the LLM fact compactor no longer re-hashes unchanged raw files on every roll. Memory temperature overlay writes run on the blocking pool and skip unchanged overlays.
- Reuse a narrow recent LLM analytics window before reconciliation to avoid repeated Parquet expansion.
- LLM trace facts materialize with less CPU: a batch stages rows in a typed DuckDB table instead of a temp JSON file, reads each new object back once before publishing instead of after, and fsyncs partitions and advances dataset watermarks once per batch. The Parquet schema, file names and replay guarantees are unchanged.
- Post-turn learning reflection no longer re-reads and deserializes every learning event log to ask whether the episode was already reflected: a per-log index of completed reflections parses each event line once and afterwards reads only appended lines (a shrunk, replaced or rewritten log is rescanned).
- The resurfacing store can hold candidates out of the curator's review window until their content revision changes or the hold expires (`hold_routing_dropped_candidates`).

### 2026-10-27 — 0.7.147

Govern commerce MCPs with installation-owned public profiles and cart quotes; improve owner channel controls and preserve supported findings.

- Keep memory snapshots warm across lookup timeouts and idle periods, and reuse unchanged source documents and lexical profiles during refreshes.
- Compact a scope's LanceDB memory index automatically once it has more than 64 active fragments (`MAGICIAN_MEMORY_INDEX_OPTIMIZE_FRAGMENTS`, `0` disables); a live index at 480 fragments searched in 771 ms, compacted to 2 in 208 ms. Prompt memory lookups log per-step index query timing.
- Pressing "new chat" on a thread that already has an untitled chat with no messages opens that chat instead of creating another empty one.
- Files a run wrote and named as delivered (a report, a spreadsheet) are attached to its answer and listed under their own names on the chat task card, newest first, up to eight.
- A research run whose last turn did not produce a usable answer no longer publishes its `COMPLETED:`/`BLOCKED:` requirement checklist as the result: the model's words in a rejected final `yield` are kept as the answer, and without any, the answer is written from the run's evidence.
- Email from someone other than the owner no longer fails with `agent_not_surface_eligible:envoy:chat`: a session bound to envoy runs on the public-envoy surface even when its bot sends no public-chat source surface.
- The owner claims their WhatsApp number or Telegram chat by sending `/claim <code>` with a one-time code from Settings → Owner identities; the verified sender is appended to the owner identities at once (hand-set identities keep working), and phone identities now match on digits (`+91 98…` matches `9198…`).
- The owner can type `/god` or `/godoff` in a chat (web, WhatsApp via Kapso, Telegram or any channel bot) to turn god mode on or off for that chat; from anyone else it is ordinary text.
- Messages from the owner's own verified WhatsApp number or Telegram chat reach the owner without the `/magic` prefix, instead of the guest envoy that could not verify them.
- Secure-request alert links default to this machine's UI host (`MAGICIAN_UI_HOST`) before the device origin, and the settings envelope warns when `owner_ui_origin` disagrees with it.
- Final answers keep what a partial run established instead of re-synthesizing it; new `make test-final-answer-live-eval` replays real runs' finalization.
- Hosted Jev moves to `jev-1.14.0` with long context, so large `tool_action_judge` requests no longer fall back to the agent model.
- A secure browser fill that failed before sending its value reports `not_filled` with a reason instead of `transport_uncertain`.
- A secure browser fill whose values the owner typed into its own prompts no longer asks a second **Use once** question.
- Google, Telegram and WhatsApp bot logins can be driven from a phone, and Telegram QR login no longer stalls on tgcli's API-key prompt.

- God mode can auto-approve (`execution.god_mode.auto_approve`, and per chat), still asking before deletes, root and code a command does not show.
- God-mode shell asks offer lasting grants for lookup/search lines such as `command -v` and `find -name '*.py'`, not just Allow once.
- Gmail, Calendar and Sheets governed calls no longer fail their profile status check with `observation_failed at lifecycle.stdout`.
- Autonomous Gmail/Calendar sends no longer fail profile selection: `account` binds to an owner-approved profile alias, shown as `From account` on the review card.
