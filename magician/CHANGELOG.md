# Changelog

All notable changes to the Magician project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

- 0.7.148: Compact long chats reliably, sized by the summarizer's window, and search their full history; list attention asks in the lane of what they need; speed up `/llm` analytics; keep whole-call tool constraints out of provider schemas; Town Square budget and resurfacing fixes.

- Chat on Anthropic models no longer fails with "input_schema does not support oneOf, allOf, or anyOf at the top level" when the `shell` or `content_*` tools are offered: their whole-call constraints stay in the canonical tool schema for candidate construction, proposal validation and dispatch, and the provider adapters and the plane MCP catalog restate them in the tool description instead of the schema root.
- `/llm` analytics batches build their reconciled `llm_calls` window once in memory (also for `epoch_ms(now() - INTERVAL …)` windows, now recognised as safe bounds) and release the analytics guard before running up to 16 cards; today's legacy `batch_*` LLM files fold hourly or at 64 files instead of staying raw until midnight; folded batches and superseded generations stay readable for 15 minutes before deletion so readers that chose them just before a fold keep working; queries past the batch cap get an explicit error result instead of being dropped; the LLM Parquet sink no longer waits unboundedly for the guard and the canonical fact compactor waits 30 s instead of 5 s. The DuckDB tool's `read_parquet` `llm_calls@` shorthand now reads the same manifest-selected files, so it no longer counts folded rows twice or picks up the `part-*` fact files.
- Town Square stops burning and misreporting its budget: an app model attempt the provider definitively rejected (typed HTTP 4xx other than 408/429) now releases its reservation instead of holding it until the month ends; a contextual round in which every tried participant failed ends the run `failed` rather than `completed`; behavior health no longer shows a `period_resource_ceiling` error after its period has ended; and consecutive failed runs of a recurring behavior back off (the interval doubled per further failure, at most 64× and one day) instead of relaunching on the interval, until a run completes.
- Preserve evidence-linked findings through task finalization and check delivery coverage separately from factual support.
- Attention asks land in the lane of what they ask for: service outages and failed agents under Failed, plan/diff approvals and action confirmations under Approvals, iteration-limit and budget pauses under Escalations, questions and sign-ins under Requests. Previously almost every ask was listed under Requests. An open ask under Failed no longer expires after two hours.
- Chat history compaction is fast and no longer fails on chats with an earlier failed turn: older tool output is trimmed to head and tail before summarizing, each summarizer call is sized to the routed summarizer model's input window alone (a long chat folds in one or two calls instead of dozens; `llm.chat_history.chunk_max_bytes` is removed, so delete it from the live config), compaction runs in the background past 70% of the budget so turns rarely wait, and the step shows **Compacting conversation · k/N**. Compaction now works in stored-transcript positions and maps onto the turn's healed request, which previously made the final save fail ("chat changed during compaction") after every summary call had run. A summary or save failure never fails a turn: a history that still fits is used in full. Text sent to the summarizer is redacted like provider replay. A compacted chat can look up exact details with the new `search_chat_history` tool, which pages long entries and whose results never count as proof of a reply.
- Browser runs treat agent-browser's `outcome_unknown` (a command that reached its daemon with no reply, and was not re-sent) as INDETERMINATE: the agent is told it may already have taken effect and to re-observe before repeating it. CloakBrowser's session-limit exit is recognised again in the patched agent-browser's wording ("Browser process exited (exit code: 76)"), so the run switches engine instead of failing.
- Tool-result cleanup probes metadata with bounded concurrency and locks only matching owners.
- A browser run launched by a conversation's first message names its tab group from that message: the conversation is titled only after its first turn, so these groups showed "✱ Chat".
- Browser runs name their tab group in the owner's Chrome: a chat launch sends the conversation's title, and any other run sends its task's title (first sentence, without the agent prefix), as Magicutor's `?label=` on connect. The same name appears on the "which browser?" card instead of "this task". Carried as `browser_tab_label` beside `browser_session_id_override`.
- Native chat now budgets model context, saves incremental history summaries and retries context overflow once while retaining the full transcript and completed tool results.
- The owner-text check (Relentless reports, chat replies, owner notifications) awaits its claim checks and delivery repair off its own frame. The delivery repair's inline LLM call had made this future large enough that a Relentless task settling at its iteration limit after an answered question overflowed its 2 MiB stack.

- The memory lifecycle pass no longer re-parses an unchanged multi-megabyte `knowledge.json` (up to three parses per run, every minute per scope): its unlocked reads share one parse keyed by size, mtime and inode (never within the 3 s racy-mtime window, dropped by every store write), and its maintenance check is read-only. Memory connection reviews get an outer timeout derived from their 60 s decision budget (`REVIEW_TIMEOUT`), and reviews that end before any decision are `deferred` instead of charged to the hourly budget.
- The shared `knowledge.json` parse is bounded (dropped after 5 min unused; at most 16 files and 32 MiB of summed file size, least recently used first). `ConnectionDecisionUnavailable` now wraps and prints its root cause. Rollback note: earlier binaries cannot deserialize the new `deferred` memory connection state.
- The notes search index no longer deletes its embeddings when an Ollama readiness check is slow (about 30% exceeded the old 200 ms limit) or an embed fails; the next refresh with Ollama embeds only the changed notes. Each such blip used to re-embed every note (~1,450 chunks, five minutes of the single Ollama slot, holding memory-index embeds for up to two minutes). Background refreshes now wait out the configured health timeout; searches keep the 200 ms budget.
- Note writes (create, save, front-matter edits, deletes) reply as soon as the file is written: the search-index refresh is queued in the background instead of awaited, so a slow embedder no longer holds a Mark done on a goal at "Saving…" for minutes.
- The 5-minute memory contradiction sweep no longer re-sends the same insight pairs to the decision engine every run (~8,300 calls/day for one agent): identical copies of an insight are folded into one item without a model call (also during `upsert_by_similarity` merges, which used to append a copy whenever review abstained), and a pair the engine answers below its gate is remembered until the engine revision changes; timeouts and other transient failures are still retried.
- Agent storage opts into memory temperature counter write-behind (`MemoryStorage::shared_handle`): a chat turn's usage and outcome counters share one overlay write per 2 s instead of rewriting the overlay each time.
- Chat turns spend less CPU on repeated parsing: procedure YAML is parsed once per file revision (shared by the procedure lookup, reflection and decision review), parsed skills are reused until a skill file changes, the trust policy is parsed once per content revision, and the LLM fact compactor no longer re-hashes unchanged raw files on every roll. Memory temperature overlay writes run on the blocking pool and skip unchanged overlays.
- Reuse a narrow recent LLM analytics window before reconciliation to avoid repeated Parquet expansion.
- LLM trace facts materialize with less CPU: a batch stages rows in a typed DuckDB table instead of a temp JSON file, reads each new object back once before publishing instead of after, and fsyncs partitions and advances dataset watermarks once per batch. The Parquet schema, file names and replay guarantees are unchanged.
- Post-turn learning reflection no longer re-reads and deserializes every learning event log to ask whether the episode was already reflected: a per-log index of completed reflections parses each event line once and afterwards reads only appended lines (a shrunk, replaced or rewritten log is rescanned).
- The resurfacing store can hold candidates out of the curator's review window until their content revision changes or the hold expires (`hold_routing_dropped_candidates`).

- 0.7.147: Govern commerce MCPs with installation-owned public profiles and cart quotes; improve owner channel controls and preserve supported findings.

- Keep memory snapshots warm across lookup timeouts and idle periods, and reuse unchanged source documents and lexical profiles during refreshes.
- Compact a scope's LanceDB memory index automatically once it has more than 64 active fragments (`MAGICIAN_MEMORY_INDEX_OPTIMIZE_FRAGMENTS`, `0` disables); a live index at 480 fragments searched in 771 ms, compacted to 2 in 208 ms. Prompt memory lookups log per-step index query timing.
- Pressing "new chat" on a thread that already has an untitled chat with no messages opens that chat instead of creating another empty one.
- Files a run wrote and named as delivered (a report, a spreadsheet) are attached to its answer and listed under their own names on the chat task card, newest first, up to eight.
- A research run whose last turn did not produce a usable answer no longer publishes its `COMPLETED:`/`BLOCKED:` requirement checklist as the result: the model's words in a rejected final `yield` are kept as the answer, and without any, the answer is written from the run's evidence.
- Email from someone other than the owner no longer fails with `agent_not_surface_eligible:envoy:chat`: a session bound to envoy runs on the public-envoy surface even when its bot sends no public-chat source surface.
- The owner claims their WhatsApp number or Telegram chat by sending `/claim <code>` with a one-time code from Settings → Owner identities; the verified sender is appended to the owner identities at once (hand-set identities keep working), and phone identities now match on digits (`+91 98…` matches `9198…`).
- The owner can type `/god` or `/godoff` in a chat (web, WhatsApp via Kapso, Telegram or any channel bot) to turn god mode on or off for that chat; from anyone else it is ordinary text.
- Messages from the owner's own verified WhatsApp number or Telegram chat reach the owner without the `/magic` prefix, instead of the guest envoy that could not verify them.
- Secure-request alert links default to this machine's UI host (`MAGICIAN_UI_HOST`) before the device origin, and the settings envelope warns when `owner_ui_origin` disagrees with it.
- Final answers keep what a partial run established instead of re-synthesizing it; new `make test-final-answer-live-eval` replays real runs' finalization.
- Hosted Jev moves to `jev-1.14.0` with long context, so large `tool_action_judge` requests no longer fall back to the agent model.
- A secure browser fill that failed before sending its value reports `not_filled` with a reason instead of `transport_uncertain`.
- A secure browser fill whose values the owner typed into its own prompts no longer asks a second **Use once** question.
- Google, Telegram and WhatsApp bot logins can be driven from a phone, and Telegram QR login no longer stalls on tgcli's API-key prompt.

- God mode can auto-approve (`execution.god_mode.auto_approve`, and per chat), still asking before deletes, root and code a command does not show.
- God-mode shell asks offer lasting grants for lookup/search lines such as `command -v` and `find -name '*.py'`, not just Allow once.
- Gmail, Calendar and Sheets governed calls no longer fail their profile status check with `observation_failed at lifecycle.stdout`.
- Autonomous Gmail/Calendar sends no longer fail profile selection: `account` binds to an owner-approved profile alias, shown as `From account` on the review card.
- MCP sign-in asks expire after ten minutes, name the service, and offer **Not now** to cancel the sign-in.
- Governed MCP runs always use the login Service accounts Connect saved, including for a non-default endpoint alias.
- Chat messages with long titles, paths or URLs keep their structured presentation, with `meta.artifact_locators` for shortened artifact ids.
- Archiving or deleting a task right after its run completes waits up to 30 s for output synthesis instead of failing with `task_active`.
- Model spend limits move to `resource_authority.model_spend` (migrated on first boot) and post to its ledger every 15 minutes.
- Delegation and handover grant transitive read access to goal workspaces; writes stay the agent's own.
- The runtime config accepts a `supervisor:` section (`manage_desktop`) for magic-supervisor; deploy this backend before adding it to a live config.
- 0.7.146: Voice terminals get conversations: `GET /devices/me/conversations` and `POST /devices/me/threads` (device-named threads in the Automated lane); an ESP32 turn with no thread of its own goes to the device's own named thread, chats in Automated threads are Automated, and `/media/tts/synthesize` can return float32 speech as 16-bit PCM (`wav_encoding: "pcm16"`).
- 0.7.146: `GET /health` reports Magician's own version as `version` (it was the magician-api crate's, so every app showed "Magician backend 0.3.67"), with `api_version` and a `versions` map (`magician`, `magician_api`, `magicutor`, `desktop` as those services report themselves). Paired devices that send `X-Magician-App-Version` have it stored on their pairing (`app_version`), shown in web Settings → Devices.
- Optional outward-send controls distinguish owner chat/delegated work, owner-created tasks and OPC work; owner web Settings saves apply immediately, with capture defaults and existing permissions preserved.
- 0.7.146: `POST /web-push/vapid` (owner) generates the server's VAPID pair, stores it in the runtime env files and turns browser Web Push on live; `MobilePushConfig` now shares its web push keys across clones so the switch reaches every holder.
- 0.7.146: Agentic flows can follow the chat engine: `execution.harness_engine: chat` (Settings → Engines → Agentic flows → "Same as Chat") resolves to the current chat engine and model on every read; `GET /plane/engines` reports `follows_chat`.
- 0.7.146: Cloudflare Access verification also accepts the dev UI host's Access application (`MAGICIAN_CF_ACCESS_UI_AUD`, comma-separated, recorded by `scripts/ensure-ui-access.sh`). Signing in through `ui-<machine>.<zone>` — a phone browser or the apps' embedded Settings — was refused with 401 because the UI host's assertion names its own application.
- Usage loading avoids duplicate reads, repeated checksums and daily Parquet binding; historical planning backfill uses bounded reads. Report bodies preserve formatting and task file edits register artifacts.
- `GET /preference-alignment/intentions` rows carry `learned_at_ms` (when memory first saved a native record), for the web's "Review what I've learned" list.

- Planning answers survive receipt reloads and affected questions can be retried; resumed proposals stay planning-only, with stack headroom for continuations.
- Governed CLI fixed environment values can bind `{scope_workdirs_home}` to the acting workspace instead of inheriting another transport's host profile.
- Chat turns know the owner's local date and time, in the owner's stated `timezone` preference (else this computer's zone); before, chat had no date or time and could not say what timezone the owner is in.
- Outward actions are no longer all held by the preference check: only preferences that can make an act wait (stated or confirmed, or inferred under a choice-based policy) are judged on the blocking path; inferred ones are judged beside it and can only nudge, never hold by failing. The engine now judges a request's intentions in parallel (it ran them one by one), Jev allows 16 calls in flight, and the check budget is 8 s. A firing act waits at most 1.5 s for the inferred ones after the blocking answer (`advisory_grace_ms`); a nudge that lands later reaches the owner as a notice. Inferred preferences are labelled in the background by whether they bear on a kind of act (Decision Engine `preference_relevance`), and a check skips the ones labelled as not applying, such as how the agent should write code; labels for deleted preferences are dropped. A decision the host never sent (its policy expired, its budget was spent or classification was switched) is reported as not dispatched, not as an engine timeout or outage.
- Cancelling, failing or deleting a task closes its plan's pending approval, which otherwise stayed in Attention and every composer dock.
- A task whose answer already contains its deliverable no longer repeats it in the published report, and an HTML page deliverable is published as the page (it showed page, narration, page).
- Chat and task memory no longer vanish when the fast and hybrid searches render one memory differently: a shortened or passage rendering is an excerpt, and excerpts of one revision merge instead of failing both stages.
- A task plan whose upfront questions were all declined finishes as a draft for approval instead of waiting on no question and replanning every ~2 minutes after a clarification answer.
- Durable planning recovery no longer overflows the 2 MiB worker stack (it crash-looped the service on restart): the recovery monitor and planning classification keep their large futures off the stack.
- Decision Model health: `GET /api/magician/v2/plane/decision-metrics/health?hours=` returns per-operation decided / unresolved / timeout / error / skipped counts, exact p50/p95 latency, the caller budget and the last closed cause code from the retained cases; decision records now carry a closed `failure` code, engine route `model_health` and `budget_ms`, and skipped invocations keep their runner status.


### 2026-10-23 — 0.7.145

- File tools: a folder spelled two ways (`~/MagicianNotes` links to `/Volumes/build/…`, the volume mounts as `/Volumes/SSD1`) is matched by directory identity, so a write inside a task workdir or allowed root is no longer refused as outside. The task workspace note lists only folders every writing tool accepts (just the workdir today: `write_file` refuses the task `outputs/`), and a refused `write_file` / `edit_file` names the task workdir and scoped workspace instead of the sandbox roots. Inside a task, a relative `write_file` / `edit_file` path now lands in the task workdir (where `read_file` looks) instead of being staged for approval under the scoped workspace.
- Chat and task Steps show a "Preparing context" row with total, memory-search and procedure timings, and say when context was partial or cancelled. Decision Engine receipts are kept in task history with their measured tokens and cost, and no longer reopen a finished run.
- Memory search is faster on large histories: recall reuses one cached candidate snapshot per scope and tier, and ordinary memories skip app checks. Lance query time is set by `runtime.retrieval.lance_query_timeout_ms` (default 3 s), and chat and task context may take up to 8 s.
- Claude chat caches its history: chat completions use a conversation prompt cache (1 h TTL), so Anthropic and Claude-via-OpenRouter calls read prior turns from cache instead of billing the whole history every call. OpenAI Responses chaining is untouched.
- Personality reaches every agent: an agent's saved personality (else its `default_personality` preset) is pinned in full into its chat system prompt and into the agent identity of every task decision prompt (delegated, triggered or scheduled), instead of competing as a ranked memory that could be dropped. Chat no longer names only the definition's default after a `switch_personality`; agents whose definitions set `default_personality` without declaring the tier now get it; contextual writing applies the selected preset's voice.
- Concurrent chat tasks no longer drive each other's tabs: each launch gets its own browser window while another launch holds the thread's window, and runs of one launch still share it. Finished and cancelled runs close every browser session they used (failed closes are retried with the id kept reserved); resumable pauses, including budget pauses, keep the window. Authenticated retrieval reads release their tabs and keep the document if cleanup fails. A run with several paired browsers asks which to use once per run. Cancelling a run that never browsed no longer retries a close of a session that does not exist.
- Provider failure: when an ordinary task's model provider keeps failing past its retry budget, the run pauses with **Retry / Cancel** instead of failing. Retry resumes from saved progress with fresh retry budgets; Cancel ends it as cancelled. Retried provider calls no longer spend the run's iterations. Delegated, controller and app runs still fail.
- Steering: a steer that arrives during a failed decision is retried, not lost; new guidance reaches the model before an approved-action replay or a churn stop, and reopens work marked complete. Steering a run that is not executing is refused.
- Background shell jobs keep running while their run is paused and across a Magician restart (re-adopted by `job_id`); they stop when the run ends or at a 72 h default deadline.
- Harness CLIs may stay silent for 1 h (was 5 min) before a turn counts as stalled (`execution.harness_turn_idle_seconds`). God mode approvals wait 30 min, and a lone Python line can be allowed for the rest of the chat or run (never "Always"). Governed MCP calls may run to the pack's declared timeout (24 h max).
- A decision the model got wrong (invalid tool arguments, unknown tool) is no longer retried as a provider hiccup when its error quotes words like `timeout`: the model now sees why the call was rejected and can fix it, instead of repeating it until the run fails. A rejected decision is recorded as such, no longer as a browser `observe` the model never made (which had reached a no-browser task's failure summary).
- Task runs are no longer offered the chat-only `delegate_to_agent` fields (`personality_mode`, `reference_task_ids`, `track_as_task`, `tutor_action`) that their delegation parser rejects; a creative delegation from a task had been refused once before every retry.
- A question a chat turn asks carries that chat's thread on its Attention row, so it also matches a newer chat in that thread and Attention can name its thread (clients already matched the asking chat by session).
- The task workspace note lists the folders this run's file tools may write, checked against its live sandbox, and leads with the task `workdir`, which every run in the task (a delegate's included) may write; a refused write inside the task names that folder. A parent had sent a delegate to `outputs/`, which the delegate's narrower sandbox refused.
- Cloud memory archive summaries run on gpt-6-luna instead of gpt-6.1-sol (`llm-router.yaml`), like the other memory jobs; they were two-thirds of memory spend.
- Unverified HTML answers render: an HTML answer published under "Not fully verified" stays HTML with the caveat as its first element, instead of showing the page source in a code block; its card summary and voice read the text, not the markup.
- Chat files: the owner can delete one file from a chat; only the chat's copy goes, the task original stays under Work, and later task updates do not re-copy it.
- Answers lead with findings: synthesis keeps bounded source excerpts from the whole run and puts gaps after the findings, also at budget stops. Browser host evidence overrides the raw page values beside it; rounded source figures (3.4K) support the same rounded claim but not an exact or derived one. Summaries and voice for "Not fully verified" answers speak the findings, not the checker's diagnostic.
- Chat can ask through `need_user_input`; decision prompts ask only for essential missing inputs before costly work and reuse earlier answers. Voice and dictation are charged to the chat they started in.

### 2026-10-23 — 0.7.144

- Spend envelope coverage: while the envelope is spent an autonomous run parks instead of calling the Decision Engine or starting a coding turn (a native decision to code is handed to Resolve as the refusal; a harness call to code ends the turn); every coding turn is charged once, cap or not; token-only harness, harness-chat and coding turns are priced; TTS/STT and realtime meeting voice are counted, never cut off; chat-launched runs count as interactive, never refused.
- Long runs: provider-outage retries are counted apart from transient retries; iterations spent parked on the spend envelope are refunded to the run's iteration ceiling (not for controller or app runs); a budget pause checkpoints the iterations already completed; delegated children are never owner-renewable.
- Approvals: the WhatsApp code-approval floor applies even with no approval rules; a governed MCP call that may have reached the server returns a non-retryable `dispatch_unknown` result instead of being sent again; MCP approvals gain a "This tool" scope.
- God mode: a lasting exact-command grant is offered only for one simple command that runs one bash/sh script, bound to the script's SHA-256 and re-checked before every run (a lone Python line can be allowed for the chat or run, never always); God mode can also be changed from a verified paired owner phone.
- Browser: the opt-in submission guard adds Approve Always (per site, revocable) and asks again if the page or draft changes while pending. With several Magician Extension browsers connected, an attended run asks which to use (decision card, default after 20 s) and a new browser raises a pairing card; unattended runs never ask.
- Governed stdio MCP runtimes: skills can run MCP servers over stdio in a scoped home, with a reviewed bindings file deciding workspace-path arguments, redaction, artifact capture and which tools are outward acts with named recipients. `executive-assistant` gets `whatsapp-mcp`; `cro` and `presentation-maker` declare CDP explicitly.
- Relentless: an omitted or 0 limit means unlimited; `propose_relentless` (pack 1.6.2) reports `closed`, `awaiting_owner_review` and a `next_step`, and a proposal reaches the owner as a request with "Review and start".

### 2026-10-23 — 0.7.143

- Browser form submissions: the guard on "Post"/"Submit"-style clicks is now an explicit opt-in (`outward_actions.browser_submission_guard`, off by default) and, when on, asks the owner instead of refusing: a `browser_submission_approval` decision card (page, control and the draft text) with Approve Once, Approve Always (a per-site standing grant in `runtime/browser/submission_grants.json`, kept until revoked) and Deny; deny or no answer stops the act and tells the agent not to retry. With the guard off no DOM probe is spent per click.
- Provider outage: a provider that is down (`ProviderUnavailable` incl. an open dispatch breaker, timeouts, queue-full, transport, HTTP 5xx) is its own decision-error kind. The run retries 6 times with doubling backoff (15 s to 5 min, about 13 min), pushes no failed record (so the stuck-loop detector cannot trip), emits `AgenticProviderOutage` (and a recovered marker), and fails with a clear message only after the budget. 429 stays an ordinary retry. Previously the breaker error fell through to Permanent and a down provider failed the run in about 15 s.
- Wall clocks give way to liveness: an ordinary task-backed root run has no 24 h ceiling unless `MAGICIAN_AGENTIC_MAX_DURATION_SECS` is set (delegated, sealed and app runs keep their deadlines; background shell jobs default to 72 h); a goal pipeline has no 3 h timer unless the agent sets `max_duration_secs`; a paused or sleeping cycle no longer counts as a circuit-breaker failure.
- A successful `SleepUntil` is a declared wait like an owned shell-job check, so a polling task is not auto-yielded as stuck (by action kind only; four identical coding runs are still caught).
- Owner spend envelope (`spend_envelope.rs`): `execution.budgets.spend_envelope`, on by default at $250 per UTC day, counted at the router for all LLM work. Autonomous classes (autonomous task, scheduled, ambient, memory, comms assist) park for the window reset or an owner grant — no per-run pause, one `spend_envelope:exhausted` attention item, an 80% warning; chat, interactive tasks, evaluation and system calls are counted but never blocked. Per-run USD valves stay at $100. The token meter no longer pauses a run while the envelope governs. Unpriced models are estimated (or blocked, `unpriced: block`).
