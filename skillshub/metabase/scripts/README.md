# Metabase CLI

`metabase-pp-cli` — a Go CLI generated by [Printing Press](https://github.com/mvanhorn/cli-printing-press)
from a curated subset of Metabase's OpenAPI spec. Replaces the previous
Specli + 3-wrapper setup with a single binary, single capability pack,
and a regeneration target you run when the curated spec changes.

## Layout

```
skillshub/metabase/
├── scripts/spec.json          # curated 93-operation spec (committed; source of truth)
├── scripts/postprocess-spec.py # rewrites operationIds + curates the full OpenAPI surface
├── scripts/refresh-spec.sh    # fetch live spec -> postprocess -> spec.json
├── bin/metabase-pp-cli        # generated binary (gitignored; built by `make regen-metabase-cli`)
├── SKILL.md                   # hand-authored analyst guide
└── .pp-build/                 # gitignored/generated Go source + PP metadata
```

## Setup (one-time)

```bash
make setup-printing-press   # installs go1.23.0 toolchain + printing-press v4.0.3
make regen-metabase-cli     # generates Go source from spec.json + builds the CLI
```

`metabase-pp-cli` then lives at `skillshub/metabase/bin/metabase-pp-cli`
(~12MB, gitignored). Skill installation/materialization copies the binary and
skill files into the scoped runtime skill directory.

## How regen and refresh differ

There are two distinct workflows:

**`make regen-metabase-cli`** — rebuild the binary from the **committed** `spec.json`. Use this on a fresh clone or after editing `spec.json` / `postprocess-spec.py`. Does **not** need a live Metabase instance; `spec.json` is the source of truth.

**`make refresh-metabase-spec`** — re-fetch the live OpenAPI from Metabase, run the postprocess, and overwrite `spec.json`. Only needed when Metabase upgrades introduce new endpoints we want to expose, or when we deliberately edit the curated path list in `postprocess-spec.py`. Requires `METABASE_BASE_URL` (and ideally a session/key) in env.

The typical lifecycle is: edit the allowlist in `postprocess-spec.py`, refresh
or regenerate `spec.json`, then regen the binary. Keep the scoped workspace copy
in sync when testing against a materialized scope.

## Daily use

The capability pack `metabase` invokes the binary directly with JSON / non-interactive flags baked into the pack's command prefix. From a shell:

```bash
source "$HOME/MagicianNotes/scopes/anonymous/default/skills/metabase/config/.env"
PP="$HOME/MagicianNotes/scopes/anonymous/default/skills/metabase/bin/metabase-pp-cli"

$PP doctor
$PP --json card list --select id,name --compact
$PP --json metabase-search --q "revenue"
```

Ad-hoc SQL via stdin (no shell-escape pain):

```bash
echo '{"database":236,"type":"native","native":{"query":"SELECT 1"}}' \
  | $PP --json dataset query --stdin
```

Inside Magician, do not use shell pipes. The inner-loop dispatcher writes the
tool call's `stdin` string to the subprocess:

```json
{
  "tool": "dataset_query",
  "arguments": {
    "stdin": "{\"database\":236,\"type\":\"native\",\"native\":{\"query\":\"SELECT 1\"}}"
  }
}
```

Saving SQL questions/cards uses the same stdin body pattern:

```json
{
  "tool": "card_create",
  "arguments": {
    "stdin": "{\"name\":\"Example\",\"display\":\"table\",\"type\":\"question\",\"dataset_query\":{\"database\":236,\"type\":\"native\",\"native\":{\"query\":\"SELECT 1\"}}}"
  }
}
```

### Auth

Two env vars in the scoped `config/.env` (Printing Press's expected names - no wrapper translation needed):

- `METABASE_BASE_URL` - Metabase instance URL (e.g. `https://your-metabase.example.com`)
- `METABASE_API_KEY` - Metabase API key (X-API-Key)

`metabase doctor` reports auth + connectivity.

### Output shapes

PP is not uniform across commands; the pack guide documents this in detail.
Quick map:

| Command group | Shape |
|---|---|
| Discovery (list/get/items/tree on database, collection, dashboard, card) | `{"meta":{"source":"live"}, "results": <api-payload>}` |
| Ad-hoc query (`dataset query`, `card run`) | `{"action":"post","success":true,"status":200,"data":<metabase-payload>,...}` |
| Export (`card export`, `dataset export`) | raw CSV/JSON/XLSX bytes (no envelope) |
| `doctor` | flat status fields |
| `metabase-search` | `{"meta":..., "results":{"data":[...],"total":N}}` |

`--compact` trims to id/name/status/timestamps; `--select <fields>` keeps
exactly the listed dotted-paths; `--csv` flattens table-shaped responses.
Errors land on stderr with typed exit codes (3 not-found, 4 auth,
5 upstream, 7 rate-limited, 10 config).

## Updating the curated spec

When Metabase upgrades or you want to expose more endpoints:

```bash
source "$HOME/MagicianNotes/scopes/anonymous/default/skills/metabase/config/.env"
make refresh-metabase-spec      # fetches $METABASE_BASE_URL/api/docs/openapi.json -> .cache/, runs postprocess
make regen-metabase-cli         # rebuilds the binary from the new spec.json
```

To add or rename endpoints, edit the `RENAMES` table in `postprocess-spec.py`.
The script also relaxes `required: true` on params/body-fields that have
`default:` (Metabase marks many tautologically-required boolean params).

The current curated surface intentionally includes analyst-relevant discovery,
execution, and controlled mutation endpoints: cards, dashboards, collections,
databases, tables, fields, dataset query/metadata/parameters, SQL snippets,
metrics, and cross-entity search. It intentionally does not expose the entire
Metabase OpenAPI surface; destructive/admin/public-link endpoints should be
added deliberately with matching `SKILL.md` guidance.

## Why Printing Press

Specli was a thin facade - three filtered specs + three bash wrappers + a
filter script. PP collapses that to one binary + one pack, and adds:

- a `--stdin` flag that eliminates the JSON-shell-escape pain on
  `/api/dataset` calls,
- `--agent`/`--compact`/`--select` global flags for agent-friendly output,
- typed exit codes the agent can branch on,
- a `doctor` subcommand for setup verification.
