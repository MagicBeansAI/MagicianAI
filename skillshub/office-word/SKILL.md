# Office Word

Tool name: `office-word`

This is the Word-specific surface over the shared OfficeCLI binary. It creates
and edits local `.docx` files without requiring Microsoft Word. Use it when the
requested deliverable must remain editable in Word: reports, proposals, memos,
letters, contracts, academic papers, formatted tables, comments, or template
merges.

Do not use it for Google Docs, PDF-only output, or a simple text response. Use
`office-excel` for `.xlsx` and `office-powerpoint` for `.pptx`.

## Required workflow

1. For an existing document, inspect it with `view` (`outline` or `annotated`)
   and targeted `get` calls before editing.
2. Preserve the input. Create a new output file unless the user explicitly
   requested an in-place edit.
3. Call `load_guidance` once per artifact: `word` normally, or
   `academic-paper` only for journal, conference, thesis, or citation-heavy work.
   Treat that guide as domain and quality guidance only. This skill's exposed
   action catalog and no-resident policy take precedence over guide examples
   that mention unavailable commands such as `open`, `save`, or `raw-set`.
4. Use L1 semantic views first, L2 paths for edits, and read-only `raw` only
   when the normal object model cannot explain the structure.
5. Run `help` before using an uncertain element or property. Never guess
   OfficeCLI property names.
6. Prefer `batch` for multiple edits so the document is opened and saved once.
7. Before delivery, run `refresh` when the document has a TOC, PAGE fields, or
   cross-references; then run `validate`, `view` mode `issues`, and a rendered
   `html` or `screenshot` check when layout matters.

## Command conventions

- Paths are 1-based. Prefer stable paths such as `p[@paraId=...]` over indices
  after inserting or deleting content.
- `extra_args` is an argv array, not a shell string. For properties use tokens
  such as `["--prop", "style=Heading1", "--prop", "bold=true"]`.
- The tool adds `--json` automatically to operational commands.
- Shell pipes, redirects, command substitutions, and installer/config commands
  are not supported.
- Auto-update and auto-resident processes are disabled by the runtime. Use `batch`
  instead of opening a persistent OfficeCLI resident.

## Safety

- Do not overwrite the only copy of a user document.
- Inspect an exact path immediately before `remove` or a broad replacement.
- Keep find/replace scoped to the smallest path that satisfies the request.
- Preserve styles, tracked changes, comments, fields, formulas, headers, and
  footers unless the request explicitly changes them.
- A successful mutation is not completion: validation and issue inspection are
  mandatory, and visual verification is required for layout-sensitive work.
