# Office PowerPoint

Tool name: `office-powerpoint`

This is the PowerPoint-specific surface over the shared OfficeCLI binary. Use
it when the user needs an editable `.pptx`: board reviews, sales decks, product
launches, technical talks, training, fundraising pitches, or targeted edits to
an existing presentation.

Use `office-word` for `.docx`, `office-excel` for `.xlsx`, and an HTML/VibeDev
workflow when the requested output is an interactive web presentation rather
than PowerPoint.

## Required workflow

1. Establish the audience, decision, presentation length, and one-sentence
   takeaway before building slides. Activate `presentation-design-principles`
   when that procedure skill is available.
2. Inspect existing decks with `view` mode `outline`, then use targeted `get`
   calls. Preserve the input and write edits to a new output unless explicitly
   told to edit in place.
3. Call `load_guidance` once per artifact: `pptx` normally, `pitch-deck` only
   for fundraising, and the Morph guides only when animation is requested.
   Treat that guide as domain and quality guidance only. This skill's exposed
   action catalog and no-resident policy take precedence over guide examples
   that mention unavailable commands such as `open`, `save`, or `raw-set`.
4. Run `help` before guessing shape, chart, image, animation, theme, note, or
   transition properties.
5. Build a claim spine and slide inventory before issuing layout commands.
   Prefer `batch` for deck construction and repeated styling.
6. Use stable `@id=` or `@name=` paths after the first inspection; positional
   shape indices shift as content is inserted or removed.
7. Before delivery, run `validate`, `view` mode `issues`, and render every slide
   with `screenshot` (a grid/contact sheet is acceptable). Inspect for overflow,
   clipping, collisions, tiny text, weak contrast, missing assets, and broken
   charts. Re-render after fixes.

## Command conventions

- `extra_args` is an argv array, not a shell string. Properties are passed as
  literal pairs such as `["--prop", "text=Revenue grew 25%", "--prop", "x=2cm"]`.
- Dimensions accept cm, in, pt, px, or EMU. Colors accept hex, named colors,
  RGB, or theme colors.
- The tool adds `--json` automatically to operational commands.
- Auto-update and auto-resident processes are disabled by the runtime. Use `batch`
  instead of opening a persistent OfficeCLI resident.

## Safety and quality

- Do not overwrite the only copy of a user deck.
- Inspect exact paths before deletion, broad replacement, movement, or swaps.
- Preserve masters, layouts, themes, notes, hyperlinks, alt text, animations,
  and hidden slides unless the request changes them.
- One slide should communicate one dominant idea; do not use OfficeCLI's broad
  feature set as permission to pack every slide with elements.
- A valid OOXML package is necessary but insufficient. A deck is complete only
  after narrative review, schema validation, issue inspection, and visual QA.
