# Impeccable — Magican procedure

Modified for Magican from Paul Bakaus's Impeccable skill-v4.8.0.
See [provenance and limitations](PROVENANCE.md), [license](LICENSE) and
[notices](NOTICE.md). This is a curated adaptation, not the full upstream toolchain.

## Activation and boundaries

Use this procedure for UI design and refinement. These workflow names express
user intent; they are not shell commands, installed slash commands or tools.
Do not run or download an upstream launcher, detector, hook or editor installer.
No API key is required. Actual edits and browser actions use existing governed
Magican tools, preserving approval and review gates. Reading this procedure
does not authorize writes, purchases, downloads or new tool installation.

1. Read the project's existing PRODUCT.md, DESIGN.md, relevant surface briefs,
   repository instructions and target implementation. Missing context is not
   permission to invent facts. For narrow refinement, preserve the incumbent
   design and proceed with known facts; offer context capture separately.
2. Select a workflow from [24-command guidance](references/commands.md). With no
   task, offer a short context-aware menu; never auto-run a workflow. `teach`
   aliases `init`; `craft` is deprecated in favor of ordinary new-work requests.
3. Read [design and verification](references/design.md) before planning or
   editing. Inspect actual rendered UI or identified, current screenshot
   fixtures where available; do not mistake filenames for visual authority.
4. Complete the scoped work, then verify affected sizes, themes, interaction
   states and accessibility using available governed tools. Report exact checks,
   outcomes and limitations. Do not claim detector coverage: it is excluded.

## Design direction

The brief wins. Refinement preserves identity, functionality and factual copy;
redesign replaces the visual world only when requested, preserving product truth
and native affordances. Ask before replacing facts, adding claims or expanding
scope. Never decorate with hate, supremacist or militarist symbols. Missing
DESIGN.md alone does not establish a greenfield project.

Choose the mode for the surface, not the entire product:
- **Persuade:** earn attention and action with a distinctive, evidence-based world.
- **Operate:** prioritize task completion, consistency and precise hierarchy.
- **Read:** prioritize comprehension, rhythm and navigation.
- **Experience:** let the artifact lead; interface chrome recedes.

For a new surface or a requested replacement world, establish audience, primary
task, content, constraints, mode and visual direction before coding. Capture only
confirmed context in project docs after approval. Do not silently repair stale
design artifacts, install hooks or rewrite the design system as a side effect.
