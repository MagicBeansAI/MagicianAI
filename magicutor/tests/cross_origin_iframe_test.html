🧪 Cross-Origin Iframe Test

This page tests typing into real cross-origin iframes (CodeSandbox, StackBlitz).

Goal: Verify that the CDP session attachment works correctly for cross-origin verification.

⚠️ Important: These are REAL cross-origin iframes. The extension needs to:
  • Detect the iframe via Target.setAutoAttach
  • Get a CDP session for the iframe
  • Use Runtime.evaluate with the session to verify text inside

Test 1: CodeSandbox (Code Editor in Cross-Origin Iframe)

CodeSandbox embeds contain a full Monaco/CodeMirror editor inside a cross-origin iframe.

This is the most challenging test - combines cross-origin + virtual DOM code editor.

Cross-Origin: codesandbox.io
Test Steps:
  1. Wait for CodeSandbox to fully load (may take 5-10 seconds)
  2. Attach debugger to this tab via Magicutor
  3. Click inside the code editor area in the iframe
  4. Use typeAtCoordinatesInFrame with the frame target ID
  5. Type: const test = 'verification works!';
  6. Check console logs for verification result
Expected: Text appears in editor. Logs show: verified: true, where: "iframe:..."
The verifyInFrame function should successfully evaluate inside the cross-origin iframe.
Failure Mode:
  • "attachFailed" - CDP session couldn't be attached to the iframe
  • "evalFailed" - Session exists but Runtime.evaluate failed
  • verified: false - Text was typed but 6-phase search didn't find it

Test 2: StackBlitz (WebContainer-based Editor)

StackBlitz uses WebContainers - an even more complex cross-origin scenario.

Cross-Origin: stackblitz.com
Test Steps:
  1. Wait for StackBlitz to fully load (may take 10-15 seconds)
  2. Click inside the index.js editor
  3. Type: console.log('stackblitz test');
  4. Verify text appears

Debug Information

Open browser DevTools (F12) and check:

  • Extension logs: Filter by [Magicutor] to see verification flow
  • Network tab: Verify iframes loaded successfully
  • Application > Frames: See iframe structure and origins
